## Process and evidence

1. Reproduce before editing application code. `node scripts/audit-flow.cjs` scrolls the **entire page with wheel events**, samples animation boundaries, reverses direction and rotates the viewport.
2. Record the symptom, underlying cause and an acceptance check for each item below.
3. Fix related root causes in small groups; perform a focused check after each group.
4. Repeat the full flow, inspect screenshots and run regression/end-to-end tests, including the actual standalone export.
5. Only update the public preview after the checks pass. Keep genuine content limitations distinct from fixed defects.

Baseline evidence: `/workspace/artifacts/viena-qa/before/flow-report.json`, 80 screenshots and four contact sheets in the same directory. Cases: desktop 1440×1000, mobile 390×844, landscape 844×390, and reduced motion 390×844. All four traversals reached the end and had no uncaught JavaScript exceptions. Those facts **did not validate the visual experience**: landscape had horizontal overflow in 39 sampled wheel positions; rotated desktop/mobile views were 1147/1136 px wide in 1000/844 px viewports. Sticky scenes were 640 px tall in a 390 px viewport. Instrumentation also recorded long main-thread tasks; these are diagnostic observations, not a cross-device frame-rate benchmark.

## Information and geography decisions

- User-supplied reference: **37 Untere Weißgerberstraße**, explicitly described by the user as possibly inexact. Use a point on the real street and an **approximate-location** annotation, not a verified building-level claim.
- The Airbnb listing and live OSM/Overpass endpoint are blocked by this environment's network policy. This is not evidence that the apartment does not exist.
- Accessible real datasets found: Vienna municipal road-network CSV in `bernhard-pfann/vienna-traffic-density`, and OpenStreetMap street geometry in `EqualStreetNames/equalstreetnames-vienna` (snapshot metadata 2026-10-02, commit `734333a5f858729a6bc227c2f8dae742af050d25`). Data must be clipped/validated and attributed; third-party executable code/pickle files are not executed.
- Ballet remains **Living Legacies**, Wiener Staatsoper, 22 January 2027, 19:00 Vienna time; Mittelloge, row 3, seats 23 and 24, as confirmed by the supplied tickets. No PDF, barcode or buyer data belongs in the preview.

### QA-23 — orientation loses the current chapter (P1, FIXED)

Rotating mid-journey can throw the reader into a different chapter even when there is no horizontal overflow. Switching between long pinned sections and short static sections changes all preceding document heights; browser scroll anchoring does not preserve the narrative location. Reproduced at journey p=.9: after rotation its bottom was -2729px above the viewport; rotating back still left it -343px above.

Fix: preserve the active section and semantic map state across responsive mode changes without interfering with normal scrolling. Acceptance: portrait→landscape→portrait keeps the accommodation reference pin visible in the same chapter.

## Validation log

- **Baseline:** completed full wheel traversals and reverse/resize sampling in all four cases. `before/flow-report.json` and contact sheets retained. No application fixes applied before collecting the baseline.
- Fixes, focused results, remaining limitations and final checks will be recorded here as they are completed.
- **Geography/local checks:** real OSM street extract generated, with provenance and ODbL metadata. An initial mobile screenshot exposed the edge of the cropped extract; the extract was extended north/south and simplified with a maximum 1.5m deviation, retaining way endpoints. The reference is the sourced street's midpoint, not a geocoded building. Desktop/mobile local screenshots and measured bounds confirm the camera keeps the reference on screen. Water geometry was not available from the accessible source, so the invented river was removed rather than replaced with another approximation.
- **Timing/local checks:** a second route issue was identified during implementation: Bézier parameter progress differs from arc-length progress. The marker now uses a length lookup matching SVG stroke distance; endpoint heading uses an analytic tangent. Browser regression checks compare the actual SVG stroke point and marker in screen coordinates.
- **Unit checks:** 13 cases passed, including real street bounds/provenance, reference distance to the street, camera bounds, curve/tangent behaviour, coherent reveal states and independent `ical.js` parsing of escaped/folded calendar output.

### Performance interpretation

The original audit's long-task list includes geometry sampling and screenshot overhead; it cannot establish a frame-rate improvement by itself. A separate capture-free wheel-flow diagnostic was therefore run (`QA_CAPTURE=0`). It recorded zero >50ms main-thread tasks in desktop, landscape and reduced-motion flow, and one 79ms task in the mobile-emulated flow. The source geometry is now memoized and street paths grouped, but these headless desktop measurements do not certify 60fps or replace profiling on physical phones. `flow-performance/flow-report.json` retains the raw diagnostic. Further optimization should follow an attributed real-device profile rather than guessing at this isolated task.
